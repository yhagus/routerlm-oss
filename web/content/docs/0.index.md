# Overview

The gateway serves its Models through three standard inference formats and a Model list. Point a client that already speaks one of these formats at the gateway's base URL, authenticate with an API Key, and use one of the gateway's Model names.

| Endpoint | Format | Page |
| --- | --- | --- |
| `POST /v1/chat/completions` | Chat Completions | [Chat Completions](/docs/chat-completions) |
| `POST /v1/messages` | Messages | [Messages](/docs/messages) |
| `POST /v1/responses` | Responses | [Responses](/docs/responses) |
| `GET /v1/models` | Model list | [Models](/docs/models) |

Each inference endpoint answers with one JSON response, or with a stream of server-sent events when the request sets `"stream": true`.

## Placeholders in the examples

Every example on these pages was run against the gateway as written. Replace the placeholders with your own values:

| Placeholder | Replace with |
| --- | --- |
| `https://gateway.example.com` | The base URL your gateway's operators gave you |
| `$ROUTERLM_API_KEY` | An environment variable holding your API Key |
| `my-model` | A Model name from [`GET /v1/models`](/docs/models) |

## What the gateway supports

On every endpoint: text, image input, streaming, function tools, reasoning, and structured output with a JSON schema. See [Sending images](/docs/images) and [Using tools](/docs/tools).

## Limits

- **Request body:** at most 20 MB, inline images included. A larger body gets `413 request_too_large`.
- **Stateless:** the gateway stores no conversations. Send the whole conversation with every request, on every endpoint. On Responses, stored responses (`store: true`), `previous_response_id` and `conversation` are refused.
- **Not supported:** audio, file and PDF input; embeddings; image generation; hosted tools such as web search, file search or code execution (only function tools are supported); stored prompts and background mode on Responses. A request that uses one of these gets `400 invalid_request` with a message that names the feature.
- **Unknown fields** the gateway has no use for are ignored rather than refused.

## Retries

The gateway may retry on your behalf before it answers. When it gives up, you get one of the errors listed on [Errors](/docs/errors).
