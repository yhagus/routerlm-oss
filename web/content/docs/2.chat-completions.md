# Chat Completions

`POST /v1/chat/completions` takes a request in the Chat Completions format and answers in the same format. Clients and SDKs built for that format work once you change their base URL to `https://gateway.example.com/v1`.

## Request

```bash
curl https://gateway.example.com/v1/chat/completions \
  -H "Authorization: Bearer $ROUTERLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [
      { "role": "system", "content": "You are a concise assistant." },
      { "role": "user", "content": "Say hello in one sentence." }
    ],
    "max_tokens": 256
  }'
```

The response is a `chat.completion` object. Its `model` is the Model name you sent, and `usage` reports the tokens used, with cached input in `usage.prompt_tokens_details.cached_tokens`.

With the `openai` SDK:

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.example.com/v1",
  apiKey: process.env.ROUTERLM_API_KEY,
});

const completion = await client.chat.completions.create({
  model: "my-model",
  messages: [{ role: "user", content: "Say hello in one sentence." }],
});

console.log(completion.choices[0].message.content);
```

## Streaming

Set `"stream": true` to receive `chat.completion.chunk` events as server-sent events, ending with `data: [DONE]`. Add `"stream_options": { "include_usage": true }` to receive a final chunk with the token usage.

```bash
curl -N https://gateway.example.com/v1/chat/completions \
  -H "Authorization: Bearer $ROUTERLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "messages": [{ "role": "user", "content": "Say hello in one sentence." }],
    "stream": true,
    "stream_options": { "include_usage": true }
  }'
```

With the `openai` SDK:

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.example.com/v1",
  apiKey: process.env.ROUTERLM_API_KEY,
});

const stream = await client.chat.completions.create({
  model: "my-model",
  messages: [{ role: "user", content: "Say hello in one sentence." }],
  stream: true,
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}
```

If the request fails after the stream has started, the last event is an error envelope (see [Errors](/docs/errors)) and no `data: [DONE]` follows.

## Other parameters

- **Reasoning:** `reasoning_effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`). Reasoning text comes back in `reasoning_content` on the message and on stream deltas.
- **Structured output:** `response_format` with `{ "type": "json_schema", "json_schema": { "name": "...", "schema": { ... } } }` or `{ "type": "json_object" }`.
- **Sampling:** `temperature`, `top_p`, `stop`, `max_tokens` or `max_completion_tokens`.
- **Images and tools:** see [Sending images](/docs/images) and [Using tools](/docs/tools).

## Refused

These get `400 invalid_request`: `n` other than 1, audio output (`audio`, `modalities`), `web_search_options`, the legacy `functions` field and `function` role (use `tools` and the `tool` role), tools other than `function`, and content parts other than text and images.
