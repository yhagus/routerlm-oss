# Models

`GET /v1/models` lists the Models your API Key may use, sorted by name. Use an `id` from this list as the `model` of an inference request.

::code-tabs
```bash
curl https://gateway.example.com/v1/models \
  -H "Authorization: Bearer $ROUTERLM_API_KEY"
```
```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.example.com/v1",
  apiKey: process.env.ROUTERLM_API_KEY,
});

for await (const model of client.models.list()) {
  console.log(model.id);
}
```
::

The response has the model-list shape that Chat Completions clients expect, plus the Model's `capabilities`:

```json
{
  "object": "list",
  "data": [
    {
      "id": "my-model",
      "object": "model",
      "created": 1794700000,
      "owned_by": "routerlm",
      "capabilities": ["vision", "tools", "reasoning", "structured-output"]
    }
  ]
}
```

`capabilities` says what a request to the Model may use:

| Capability | Requests that need it |
| --- | --- |
| `vision` | [Image input](/docs/images) |
| `tools` | [Function tools](/docs/tools) |
| `reasoning` | Reasoning effort or thinking settings |
| `structured-output` | A JSON schema response format |

A request that needs a capability the Model doesn't have gets `400 no_capable_route`.
