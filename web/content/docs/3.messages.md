# Messages

`POST /v1/messages` takes a request in the Messages format and answers in the same format. Clients and SDKs built for that format work once you change their base URL to `https://gateway.example.com`. As in the Messages format, every request must set `max_tokens`.

## Request

::code-tabs
```bash
curl https://gateway.example.com/v1/messages \
  -H "x-api-key: $ROUTERLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "max_tokens": 256,
    "system": "You are a concise assistant.",
    "messages": [{ "role": "user", "content": "Say hello in one sentence." }]
  }'
```
```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://gateway.example.com",
  apiKey: process.env.ROUTERLM_API_KEY,
});

const message = await client.messages.create({
  model: "my-model",
  max_tokens: 256,
  messages: [{ role: "user", content: "Say hello in one sentence." }],
});

console.log(message.content);
```
::

The response is a `message` object. Its `model` is the Model name you sent, and `usage` reports `input_tokens`, `output_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens`.

## Streaming

Set `"stream": true` to receive named server-sent events: `message_start`, then `content_block_start`, `content_block_delta` and `content_block_stop` for each block, then `message_delta` with the stop reason and the token usage, then `message_stop`.

::code-tabs
```bash
curl -N https://gateway.example.com/v1/messages \
  -H "x-api-key: $ROUTERLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-model",
    "max_tokens": 256,
    "messages": [{ "role": "user", "content": "Say hello in one sentence." }],
    "stream": true
  }'
```
```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://gateway.example.com",
  apiKey: process.env.ROUTERLM_API_KEY,
});

const stream = client.messages
  .stream({
    model: "my-model",
    max_tokens: 256,
    messages: [{ role: "user", content: "Say hello in one sentence." }],
  })
  .on("text", (text) => process.stdout.write(text));

const message = await stream.finalMessage();
console.log(message.usage);
```
::

If the request fails after the stream starts, the last event is `event: error` with an error body (see [Errors](/docs/errors)) and no `message_stop` follows.

## Other parameters

- **Reasoning:** `thinking` (`enabled` with `budget_tokens`, `adaptive`, or `disabled`) and `output_config.effort`. Thinking blocks come back with their `signature`. Send them back unchanged in later turns.
- **Structured output:** `output_config.format` with `{ "type": "json_schema", "schema": { ... } }`.
- **Prompt caching:** the gateway applies `cache_control` on system, text, image, tool and tool result blocks, and at the top level.
- **Sampling:** `temperature`, `top_p`, `stop_sequences`.
- **Images and tools:** see [Sending images](/docs/images) and [Using tools](/docs/tools).

## Not supported

These get `400 invalid_request`:

- Server tools: any tool type other than a custom tool.
- Content blocks other than text, image, tool use, tool result and thinking, such as `document` and `search_result`.
- Image sources other than `base64` and `url`, such as `file`.
- `role: "system"` inside `messages`. Use `system` instead.
- `mcp_servers`.
