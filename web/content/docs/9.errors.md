# Errors

A failed request gets an HTTP error status and a JSON error body in the endpoint's own format. The error handling in your client or SDK keeps working. Every error carries one of the codes below.

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | `invalid_request` | The body is malformed, uses a feature the gateway doesn't support, or names a Model of another Kind than the endpoint serves. The message says which. | Fix the request. Retrying it unchanged fails again. |
| 400 | `no_capable_route` | The Model can't serve what the request needs, such as images, tools, reasoning or a JSON schema, a conversation this long, or a media request's size, length or input images. | Check the Model's `capabilities` in [`GET /v1/models`](/docs/models), then use another Model or drop the feature. |
| 401 | `invalid_api_key` | The API Key is missing, wrong, revoked or expired. | Send a valid key (see [Authentication](/docs/authentication)), or ask the gateway's operators for a new one. |
| 402 | `spend_limit_reached` | Your API Key reached its Spend Limit. A request already running when the limit was reached still finishes. | Don't retry: ask whoever issued the key to raise its Spend Limit. |
| 403 | `model_not_allowed` | Your API Key isn't allowed to use this Model. | Use a Model listed by `GET /v1/models`, or ask the operators to allow this one. |
| 404 | `model_not_found` | No enabled Model has this name. | Check the name against `GET /v1/models`. |
| 404 | `video_not_found` | The gateway didn't issue this video id to your API Key, or the video expired or its Provider Account is gone. | Check the id returned by `POST /v1/videos`, and use the same API Key. Submit a new Video Job if it expired. |
| 409 | `video_not_ready` | The Video Job isn't completed yet, so its content can't be downloaded. | Poll `GET /v1/videos/{id}` until `status` is `completed`, then download. |
| 413 | `request_too_large` | The request body is over 20 MB, or a file uploaded in a multipart form is over 25 MB. | Send a smaller body: shrink or resize inline images, or send images by URL. Split long audio into shorter files. |
| 429 | `upstream_rate_limited` | The gateway retried on your behalf, and every try was rate limited. | Wait, then retry with exponential backoff. |
| 502 | `upstream_error` | The gateway retried on your behalf, and every try failed. | Retry later with backoff. |
| 504 | `upstream_timeout` | The gateway retried on your behalf, and every try timed out. | Retry later. A smaller `max_tokens` or a shorter conversation can help. |

## Error body format

Chat Completions, Responses and the [image, audio and video endpoints](/docs/media) send this error body, with the code in `error.code`:

```json
{
  "error": {
    "message": "The Model \"unknown-model\" does not exist",
    "type": "invalid_request_error",
    "param": null,
    "code": "model_not_found"
  }
}
```

Messages sends this error body. `error.type` is the Messages error type, and `error.code` is the gateway's code:

```json
{
  "type": "error",
  "error": {
    "type": "not_found_error",
    "message": "The Model \"unknown-model\" does not exist",
    "code": "model_not_found"
  }
}
```

The `error.message` text is for people to read, and it may change. Match on `error.code`.

## Errors during a stream

After a stream starts, the HTTP status is already `200`. If the request fails after that, the stream ends with an error event in the endpoint's format, not with its normal ending:

- Chat Completions: an error body as the last `data:` line, with no `data: [DONE]`.
- Messages and Responses: an `event: error`.

Treat the output you received before the error as incomplete.
