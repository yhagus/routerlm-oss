# Integrations

An Integration is a business application, such as a SaaS that resells inference, that the gateway's operators connect to the gateway. It issues API Keys to its own Customers, sets each key's Spend Limit and Request Rate, and pulls the Usage Logs of those keys. A Customer is one of your buyers, known to the gateway only by the id you give it. The gateway keeps no profile, balance or plan for a Customer.

Your Customers call the inference endpoints with the API Keys you issue them, as described on the other pages. Your application manages those keys through the control plane on this page.

## The Integration Secret

Every control plane call authenticates with your Integration Secret. Ask the gateway's operators for one: it starts with `rlmi_`, and it is shown only once, so keep it in a safe place on your server. The operators can rotate it or disable your Integration. The Integration Secret never calls the inference endpoints, and an API Key never calls the control plane.

Send the Integration Secret as a Bearer token. Every operation sees only your Integration's API Keys and Usage Logs:

```bash
curl https://gateway.example.com/integration/v1/models \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

The examples use these placeholders on top of the ones on [Overview](/docs#placeholders-in-the-examples):

| Placeholder | Replace with |
| --- | --- |
| `$ROUTERLM_INTEGRATION_SECRET` | An environment variable holding your Integration Secret |
| `0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b` | The `id` of one of your API Keys |
| `customer-42` | Your own id for a Customer |

## Issuing an API Key

`POST /integration/v1/keys` issues an API Key to a Customer and answers `201`:

```bash
curl https://gateway.example.com/integration/v1/keys \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "customer-42",
    "name": "Customer 42 production",
    "spendLimit": 25,
    "requestRate": 60
  }'
```

| Field | Meaning |
| --- | --- |
| `customerId` | Required. Your id for the Customer, up to 200 characters. It never changes. |
| `name` | A label for the key, up to 100 characters. Defaults to `customerId`. |
| `expiresAt` | When the key stops working, as an RFC 3339 time in the future. Left out or `null`: never. |
| `allowedModelIds` | The `id`s of the Models the key may use, from [`GET /integration/v1/models`](#listing-models). Left out or empty: every Model your Integration may sell. |
| `spendLimit` | The key's Spend Limit: the most Cost, in USD, it may run up. Left out or `null`: no limit. |
| `requestRate` | The key's Request Rate: the most requests per minute it may send. Left out or `null`: no limit. |

The response holds the API Key in `key`. Give it to your Customer: the gateway never shows it again.

```json
{
  "apiKey": {
    "id": "0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b",
    "keyId": "k7x2m9q4",
    "name": "Customer 42 production",
    "customerId": "customer-42",
    "createdAt": "2026-11-21T09:30:00.000Z",
    "allowedModelIds": [],
    "spendLimit": 25,
    "spent": 0,
    "requestRate": 60
  },
  "key": "rlm_k7x2m9q4_…"
}
```

`apiKey` describes the key, and every other operation returns it in this shape. `spent` is the Cost the key has run up so far. A field that isn't set, such as `expiresAt` here, is left out. `revokedAt` appears once the key is revoked.

## Listing API Keys

`GET /integration/v1/keys` lists your API Keys, newest first. `customerId` keeps only one Customer's keys:

```bash
curl "https://gateway.example.com/integration/v1/keys?customerId=customer-42&pageSize=50" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

The response is `{"keys": [...], "nextPageToken": "..."}`. `pageSize` is 1 to 100 and defaults to 50. When `nextPageToken` is present, send it as `pageToken` to get the next page.

## Getting an API Key

`GET /integration/v1/keys/{id}` returns one API Key, with what it has `spent` so far:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

## Updating an API Key

`PATCH /integration/v1/keys/{id}` changes the fields you send and leaves the others as they are. A field sent as `null` is cleared, so `"spendLimit": null` removes the Spend Limit. You can change `name`, `expiresAt`, `allowedModelIds`, `spendLimit` and `requestRate`, but not `customerId`:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b \
  -X PATCH \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"spendLimit": 50, "requestRate": 120}'
```

A new Spend Limit or Request Rate applies to the Customer's next requests. Raising a Spend Limit above what the key has spent lets it send requests again.

## Rotating an API Key

`POST /integration/v1/keys/{id}/rotate` gives the API Key a new key, with a new `keyId`, and keeps its `id`, Customer, limits and what it has spent. The old key stops working. The response has the same shape as when you [issue a key](#issuing-an-api-key), with the new key in `key`:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b/rotate \
  -X POST \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

## Revoking an API Key

`POST /integration/v1/keys/{id}/revoke` stops the key for good and returns it with `revokedAt` set. Revoking a revoked key changes nothing:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b/revoke \
  -X POST \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

A revoked key can't be updated or rotated. Issue a new one instead.

## Listing Models

`GET /integration/v1/models` lists the Models your Integration may sell, with their prices, so you can bill your Customers:

```bash
curl https://gateway.example.com/integration/v1/models \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

```json
{
  "models": [
    {
      "id": "5b1c9d2e-7a3f-4b6c-8d0e-2f4a6c8e0b1d",
      "name": "my-model",
      "kind": "chat",
      "capabilities": ["vision", "tools"],
      "inputPrice": 3,
      "outputPrice": 15
    }
  ]
}
```

Your Customers send `name` as the `model` of an inference request. Use `id` in `allowedModelIds`. `kind` and `capabilities` mean the same as on [Models](/docs/models). Prices are in USD: `inputPrice`, `outputPrice`, `cacheReadPrice` and `cacheWritePrice` per million tokens for chat Models, and the `pricePer…` fields for image, speech, transcription and video Models. A price that isn't set is left out.

## Pulling usage

`GET /integration/v1/usage-logs` returns the Usage Logs of your Customers' requests, one per request, oldest first. Start without `after`:

```bash
curl "https://gateway.example.com/integration/v1/usage-logs?pageSize=100" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

```json
{
  "usageLogs": [
    {
      "id": "9c3e5a7b-1d2f-4a6b-8c0d-4e6f8a0b2c3d",
      "receivedAt": "2026-11-21T09:31:12.000Z",
      "apiKeyId": "0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b",
      "apiKeyName": "Customer 42 production",
      "customerId": "customer-42",
      "modelName": "my-model",
      "kind": "chat",
      "clientProtocol": "openai-chat",
      "streamed": false,
      "httpStatus": 200,
      "inputTokens": 1200,
      "outputTokens": 300,
      "cost": 0.0081,
      "durationMs": 2140,
      "cancelled": false,
      "incomplete": false
    }
  ],
  "nextCursor": "MTIzNDU2Nzo0Mg"
}
```

Then send the `nextCursor` you got back as `after` to get the Usage Logs that came since:

```bash
curl "https://gateway.example.com/integration/v1/usage-logs?after=MTIzNDU2Nzo0Mg&pageSize=100" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

`pageSize` is 1 to 1000 and defaults to 100. `cost` is in USD and is left out when the Cost isn't known. A failed request has its `httpStatus` and `errorCode`, so you can tell your Customer why it failed.

The cursor makes billing safe:

- **Never skips, never repeats.** Each Usage Log comes exactly once if you always pass the last `nextCursor` you got. Store the cursor together with what you did with the page, and start from the stored cursor after a restart.
- **Ordered by when it was written, then by sequence.** Usage Logs come in the order the gateway committed them. That is close to, but not always exactly, the order of `receivedAt`.
- **May lag.** A Usage Log appears once it and the writes before it are committed, usually a few seconds after the request ends. A request still running has no Usage Log yet.
- **Opaque.** Don't build or change a cursor. A malformed one gets `400 INVALID_ARGUMENT`. When there is nothing new, the page is empty and `nextCursor` is the cursor you sent, so poll again later with the same one.

## gRPC

The same operations are available over gRPC, with the same fields and results. The contract is [`control_plane.proto`](https://github.com/yhagus/routerlm-oss/blob/main/src/control-plane/data/control_plane.proto), at `src/control-plane/data/control_plane.proto` in the gateway's repository. It defines the service `routerlm.integration.v1.ControlPlane`. Generate a client from it with your language's gRPC tools.

- **Address:** ask the gateway's operators. The gRPC server runs only when they set `CONTROL_PLANE_PORT`, and it is reachable only from their private network.
- **Transport:** plaintext HTTP/2 (h2c), with no TLS, unless the operators put a TLS proxy in front of it.
- **Authentication:** send the Integration Secret in the `authorization` metadata, as `Bearer rlmi_…`.

## Errors from the control plane

A failed call gets an HTTP status and a body with the gRPC status name and a message. Over gRPC you get the matching status code:

```json
{
  "code": "NOT_FOUND",
  "message": "API Key not found"
}
```

| HTTP status | gRPC status | Meaning |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | The request is malformed: a missing `customerId`, a Model outside what your Integration may sell, an expiry in the past, or a malformed cursor. The message says which. |
| 401 | `UNAUTHENTICATED` | The Integration Secret is missing, wrong or rotated away, or your Integration is disabled. |
| 404 | `NOT_FOUND` | No API Key of your Integration has this id. |
| 409 | `FAILED_PRECONDITION` | The API Key is revoked, so it can't be updated or rotated. |

Match on `code`. The `message` text is for people to read, and it may change.

## Errors your Customers can get

On top of the usual inference errors, the limits you set refuse a Customer's requests with these errors. See [Errors](/docs/errors).

- `402 spend_limit_reached`: the API Key reached its Spend Limit. A request already running still finishes, so `spent` can go slightly past the limit. The key works again once you raise or clear its Spend Limit.
- `429 request_rate_exceeded`: the API Key sent more requests this minute than its Request Rate allows. The Customer can retry within a minute.
