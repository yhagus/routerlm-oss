# Error

_Request_ yang gagal mendapat status HTTP _error_ dan _error body_ JSON dalam format _endpoint_ tersebut. _Error handling_ di _client_ atau SDK Anda tetap berjalan seperti biasa. Setiap _error_ berisi salah satu kode di bawah.

| Status | Kode | Arti | Yang perlu dilakukan |
| --- | --- | --- | --- |
| 400 | `invalid_request` | _Request body_ tidak valid, memakai fitur yang tidak didukung _gateway_, atau menyebut Model dengan Kind yang tidak dilayani _endpoint_ tersebut. `error.message` menyebutkan masalahnya. | Perbaiki _request_. _Request_ yang dikirim ulang tanpa perubahan akan gagal lagi. |
| 400 | `no_capable_route` | Model tidak bisa memenuhi kebutuhan _request_, misalnya gambar, _tool_, _reasoning_, JSON schema, percakapan sepanjang ini, atau ukuran, durasi, atau gambar _input_ di _request_ media. | Cek `capabilities` milik Model di [`GET /v1/models`](/id/docs/models). Lalu pakai Model lain, atau hapus fitur tersebut dari _request_. |
| 401 | `invalid_api_key` | API Key tidak ada, salah, dicabut, atau kedaluwarsa. | Kirim API Key yang valid (lihat [Autentikasi](/id/docs/authentication)), atau minta API Key baru ke operator _gateway_. |
| 402 | `spend_limit_reached` | API Key Anda sudah mencapai Spend Limit-nya. Request yang sudah berjalan saat batas tercapai tetap selesai. | Jangan ulangi request: minta pihak yang menerbitkan key menaikkan Spend Limit-nya. |
| 403 | `model_not_allowed` | API Key Anda tidak diizinkan memakai Model ini. | Pakai Model yang ada di `GET /v1/models`, atau minta operator mengizinkan Model ini. |
| 404 | `model_not_found` | Tidak ada Model aktif dengan nama ini. | Cocokkan nama Model dengan `GET /v1/models`. |
| 404 | `video_not_found` | _Gateway_ tidak menerbitkan id video ini untuk API Key Anda, atau videonya sudah kedaluwarsa, atau Provider Account-nya sudah tidak ada. | Cek id dari `POST /v1/videos` dan pakai API Key yang sama. Kirim Video Job baru jika sudah kedaluwarsa. |
| 409 | `video_not_ready` | Video Job belum selesai, jadi kontennya belum bisa diunduh. | _Poll_ `GET /v1/videos/{id}` sampai `status` bernilai `completed`, lalu unduh. |
| 413 | `request_too_large` | _Request body_ lebih dari 20 MB, atau _file_ yang diunggah lewat _multipart form_ lebih dari 25 MB. | Perkecil _request body_: kecilkan ukuran atau resolusi gambar _inline_, atau kirim gambar lewat URL. Pecah audio yang panjang menjadi beberapa _file_ yang lebih pendek. |
| 429 | `request_rate_exceeded` | API Key Anda mengirim lebih banyak request dalam satu menit daripada yang diizinkan Request Rate-nya. | Tunggu hingga satu menit, lalu _retry_ dengan _exponential backoff_, atau minta pihak yang menerbitkan key menaikkan Request Rate-nya. |
| 429 | `upstream_rate_limited` | _Gateway_ sudah melakukan _retry_ atas nama Anda, dan semua percobaan kena _rate limit_. | Tunggu sebentar, lalu _retry_ dengan _exponential backoff_. |
| 502 | `upstream_error` | _Gateway_ sudah melakukan _retry_ atas nama Anda, dan semua percobaan gagal. | _Retry_ lagi nanti dengan _backoff_. |
| 504 | `upstream_timeout` | _Gateway_ sudah melakukan _retry_ atas nama Anda, dan semua percobaan _timeout_. | _Retry_ lagi nanti. Nilai `max_tokens` yang lebih kecil atau percakapan yang lebih pendek bisa membantu. |

## Format error body

Chat Completions, Responses, dan [_endpoint_ gambar, audio, dan video](/id/docs/media) mengirim _error body_ seperti ini, dengan kode di `error.code`:

```json
{
  "error": {
    "message": "The Model \"unknown-model\" does not exist",
    "type": "invalid_request_error",
    "param": null,
    "code": "model_not_found"
  }
}
```

Messages mengirim _error body_ seperti ini. `error.type` berisi tipe _error_ Messages, dan `error.code` berisi kode dari _gateway_:

```json
{
  "type": "error",
  "error": {
    "type": "not_found_error",
    "message": "The Model \"unknown-model\" does not exist",
    "code": "model_not_found"
  }
}
```

Teks `error.message` ditujukan untuk dibaca manusia dan bisa berubah. Pakai `error.code` untuk mencocokkan _error_.

## Error saat streaming

Begitu _stream_ dimulai, status HTTP sudah terkirim sebagai `200`. Jika _request_ gagal setelah itu, _stream_ diakhiri dengan _event_ _error_ dalam format _endpoint_ tersebut, bukan dengan penutup normalnya:

- Chat Completions: _error body_ di baris `data:` terakhir, tanpa `data: [DONE]`.
- Messages dan Responses: `event: error`.

Anggap _output_ yang Anda terima sebelum _error_ itu belum lengkap.
