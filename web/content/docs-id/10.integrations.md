# Integration

Integration adalah aplikasi bisnis, misalnya SaaS yang menjual ulang inferensi, yang dihubungkan operator ke _gateway_. Integration menerbitkan API Key untuk Customer-nya sendiri, mengatur Spend Limit dan Request Rate setiap key, dan menarik Usage Log dari key tersebut. Customer adalah pembeli Anda, yang dikenal _gateway_ hanya lewat id yang Anda berikan. _Gateway_ tidak menyimpan profil, saldo, atau paket apa pun untuk Customer.

Customer Anda memanggil _endpoint_ inferensi dengan API Key yang Anda terbitkan, seperti dijelaskan di halaman lain. Aplikasi Anda mengelola key tersebut lewat _control plane_ di halaman ini.

## Integration Secret

Setiap panggilan ke _control plane_ diautentikasi dengan Integration Secret Anda. Minta Integration Secret kepada operator _gateway_: awalannya `rlmi_`, dan hanya ditampilkan satu kali, jadi simpan di tempat yang aman di _server_ Anda. Operator bisa melakukan rotasi atau menonaktifkan Integration Anda. Integration Secret tidak pernah bisa memanggil _endpoint_ inferensi, dan API Key tidak pernah bisa memanggil _control plane_.

Kirim Integration Secret sebagai Bearer token. Setiap operasi hanya melihat API Key dan Usage Log milik Integration Anda:

```bash
curl https://gateway.example.com/integration/v1/models \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

Selain _placeholder_ di [Ringkasan](/id/docs#placeholder-di-contoh), contoh di halaman ini memakai _placeholder_ berikut:

| Placeholder | Ganti dengan |
| --- | --- |
| `$ROUTERLM_INTEGRATION_SECRET` | _Environment variable_ yang berisi Integration Secret Anda |
| `0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b` | `id` salah satu API Key Anda |
| `customer-42` | Id Customer milik Anda sendiri |

## Menerbitkan API Key

`POST /integration/v1/keys` menerbitkan API Key untuk seorang Customer dan membalas dengan `201`:

```bash
curl https://gateway.example.com/integration/v1/keys \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "customer-42",
    "name": "Customer 42 production",
    "spendLimit": 25,
    "requestRate": 60
  }'
```

| Field | Arti |
| --- | --- |
| `customerId` | Wajib. Id Customer milik Anda, maksimal 200 karakter. Tidak pernah berubah. |
| `name` | Label key, maksimal 100 karakter. _Default_-nya `customerId`. |
| `expiresAt` | Kapan key berhenti berlaku, sebagai waktu RFC 3339 di masa depan. Tidak dikirim atau `null`: tidak pernah kedaluwarsa. |
| `allowedModelIds` | `id` Model yang boleh dipakai key, dari [`GET /integration/v1/models`](#daftar-model). Tidak dikirim atau kosong: semua Model yang boleh dijual Integration Anda. |
| `spendLimit` | Spend Limit key: Cost maksimal, dalam USD, yang boleh dihabiskan key. Tidak dikirim atau `null`: tanpa batas. |
| `requestRate` | Request Rate key: jumlah _request_ maksimal per menit. Tidak dikirim atau `null`: tanpa batas. |

_Response_ berisi API Key di `key`. Berikan key ini kepada Customer Anda: _gateway_ tidak akan menampilkannya lagi.

```json
{
  "apiKey": {
    "id": "0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b",
    "keyId": "k7x2m9q4",
    "name": "Customer 42 production",
    "customerId": "customer-42",
    "createdAt": "2026-11-21T09:30:00.000Z",
    "allowedModelIds": [],
    "spendLimit": 25,
    "spent": 0,
    "requestRate": 60
  },
  "key": "rlm_k7x2m9q4_…"
}
```

`apiKey` menjelaskan key tersebut, dan setiap operasi lain mengembalikannya dalam bentuk yang sama. `spent` adalah Cost yang sudah dihabiskan key sejauh ini. _Field_ yang tidak diisi, seperti `expiresAt` di sini, tidak disertakan. `revokedAt` muncul setelah key dicabut.

## Daftar API Key

`GET /integration/v1/keys` menampilkan daftar API Key Anda, dari yang terbaru. `customerId` menyaring key milik satu Customer saja:

```bash
curl "https://gateway.example.com/integration/v1/keys?customerId=customer-42&pageSize=50" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

_Response_-nya berbentuk `{"keys": [...], "nextPageToken": "..."}`. `pageSize` bernilai 1 sampai 100, dengan _default_ 50. Jika ada `nextPageToken`, kirim nilainya sebagai `pageToken` untuk mengambil halaman berikutnya.

## Mengambil API Key

`GET /integration/v1/keys/{id}` mengembalikan satu API Key, beserta `spent`-nya sejauh ini:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

## Mengubah API Key

`PATCH /integration/v1/keys/{id}` mengubah _field_ yang Anda kirim dan membiarkan yang lain. _Field_ yang dikirim sebagai `null` dikosongkan, jadi `"spendLimit": null` menghapus Spend Limit. Anda bisa mengubah `name`, `expiresAt`, `allowedModelIds`, `spendLimit`, dan `requestRate`, tetapi tidak `customerId`:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b \
  -X PATCH \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"spendLimit": 50, "requestRate": 120}'
```

Spend Limit atau Request Rate yang baru berlaku untuk _request_ Customer berikutnya. Menaikkan Spend Limit di atas jumlah yang sudah dihabiskan key membuat key bisa mengirim _request_ lagi.

## Rotasi API Key

`POST /integration/v1/keys/{id}/rotate` memberi API Key sebuah key baru, dengan `keyId` baru, dan tetap mempertahankan `id`, Customer, batas, dan jumlah yang sudah dihabiskannya. Key lama berhenti berlaku. _Response_-nya berbentuk sama seperti saat Anda [menerbitkan key](#menerbitkan-api-key), dengan key baru di `key`:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b/rotate \
  -X POST \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

## Mencabut API Key

`POST /integration/v1/keys/{id}/revoke` menghentikan key untuk selamanya dan mengembalikannya dengan `revokedAt` terisi. Mencabut key yang sudah dicabut tidak mengubah apa pun:

```bash
curl https://gateway.example.com/integration/v1/keys/0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b/revoke \
  -X POST \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

Key yang sudah dicabut tidak bisa diubah atau dirotasi. Terbitkan key baru sebagai gantinya.

## Daftar Model

`GET /integration/v1/models` menampilkan daftar Model yang boleh dijual Integration Anda, beserta harganya, supaya Anda bisa menagih Customer Anda:

```bash
curl https://gateway.example.com/integration/v1/models \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

```json
{
  "models": [
    {
      "id": "5b1c9d2e-7a3f-4b6c-8d0e-2f4a6c8e0b1d",
      "name": "my-model",
      "kind": "chat",
      "capabilities": ["vision", "tools"],
      "inputPrice": 3,
      "outputPrice": 15
    }
  ]
}
```

Customer Anda mengirim `name` sebagai `model` di _request_ inferensi. Pakai `id` di `allowedModelIds`. Arti `kind` dan `capabilities` sama seperti di [Daftar Model](/id/docs/models). Harga dalam USD: `inputPrice`, `outputPrice`, `cacheReadPrice`, dan `cacheWritePrice` per sejuta _token_ untuk Model _chat_, dan _field_ `pricePer…` untuk Model gambar, _speech_, transkripsi, dan video. Harga yang tidak diisi tidak disertakan.

## Menarik pemakaian

`GET /integration/v1/usage-logs` mengembalikan Usage Log dari _request_ Customer Anda, satu per _request_, dari yang terlama. Mulai tanpa `after`:

```bash
curl "https://gateway.example.com/integration/v1/usage-logs?pageSize=100" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

```json
{
  "usageLogs": [
    {
      "id": "9c3e5a7b-1d2f-4a6b-8c0d-4e6f8a0b2c3d",
      "receivedAt": "2026-11-21T09:31:12.000Z",
      "apiKeyId": "0f8e2b6a-3c1d-4e5f-9a7b-6c4d2e1f0a9b",
      "apiKeyName": "Customer 42 production",
      "customerId": "customer-42",
      "modelName": "my-model",
      "kind": "chat",
      "clientProtocol": "openai-chat",
      "streamed": false,
      "httpStatus": 200,
      "inputTokens": 1200,
      "outputTokens": 300,
      "cost": 0.0081,
      "durationMs": 2140,
      "cancelled": false,
      "incomplete": false
    }
  ],
  "nextCursor": "MTIzNDU2Nzo0Mg"
}
```

Lalu kirim `nextCursor` yang Anda terima sebagai `after` untuk mengambil Usage Log yang masuk sesudahnya:

```bash
curl "https://gateway.example.com/integration/v1/usage-logs?after=MTIzNDU2Nzo0Mg&pageSize=100" \
  -H "Authorization: Bearer $ROUTERLM_INTEGRATION_SECRET"
```

`pageSize` bernilai 1 sampai 1000, dengan _default_ 100. `cost` dalam USD dan tidak disertakan jika Cost-nya tidak diketahui. _Request_ yang gagal memiliki `httpStatus` dan `errorCode`, jadi Anda bisa memberi tahu Customer penyebabnya.

_Cursor_ membuat penagihan aman:

- **Tidak pernah terlewat, tidak pernah berulang.** Setiap Usage Log muncul tepat satu kali jika Anda selalu mengirim `nextCursor` terakhir yang Anda terima. Simpan _cursor_ bersama hasil pemrosesan halaman tersebut, dan mulai lagi dari _cursor_ yang tersimpan setelah _restart_.
- **Urut sesuai waktu penulisan, lalu sesuai urutan nomor.** Usage Log muncul sesuai urutan _gateway_ menyimpannya. Urutan ini mendekati urutan `receivedAt`, tetapi tidak selalu sama persis.
- **Bisa tertinggal.** Usage Log muncul setelah Usage Log itu dan penulisan sebelumnya tersimpan, biasanya beberapa detik setelah _request_ selesai. _Request_ yang masih berjalan belum memiliki Usage Log.
- **Tidak transparan.** Jangan membuat atau mengubah _cursor_ sendiri. _Cursor_ yang tidak valid mendapat `400 INVALID_ARGUMENT`. Jika tidak ada data baru, halamannya kosong dan `nextCursor` sama dengan _cursor_ yang Anda kirim, jadi _poll_ lagi nanti dengan _cursor_ yang sama.

## gRPC

Operasi yang sama tersedia lewat gRPC, dengan _field_ dan hasil yang sama. Kontraknya adalah [`control_plane.proto`](https://github.com/yhagus/routerlm-oss/blob/main/src/control-plane/data/control_plane.proto), di `src/control-plane/data/control_plane.proto` dalam _repository_ _gateway_. File ini mendefinisikan _service_ `routerlm.integration.v1.ControlPlane`. Buat _client_ dari file ini dengan _tool_ gRPC untuk bahasa pemrograman Anda.

- **Alamat:** tanyakan kepada operator _gateway_. _Server_ gRPC hanya berjalan jika operator mengisi `CONTROL_PLANE_PORT`, dan hanya bisa dijangkau dari jaringan privat mereka.
- **Transport:** HTTP/2 tanpa enkripsi (h2c), tanpa TLS, kecuali operator memasang _proxy_ TLS di depannya.
- **Autentikasi:** kirim Integration Secret di _metadata_ `authorization`, sebagai `Bearer rlmi_…`.

## Error dari control plane

Panggilan yang gagal mendapat status HTTP dan _body_ berisi nama status gRPC dan pesan. Lewat gRPC, Anda mendapat kode status yang sesuai:

```json
{
  "code": "NOT_FOUND",
  "message": "API Key not found"
}
```

| Status HTTP | Status gRPC | Arti |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | _Request_ tidak valid: `customerId` tidak ada, Model di luar yang boleh dijual Integration Anda, waktu kedaluwarsa di masa lalu, atau _cursor_ tidak valid. Pesannya menyebutkan masalahnya. |
| 401 | `UNAUTHENTICATED` | Integration Secret tidak ada, salah, atau sudah dirotasi, atau Integration Anda dinonaktifkan. |
| 404 | `NOT_FOUND` | Tidak ada API Key milik Integration Anda dengan id ini. |
| 409 | `FAILED_PRECONDITION` | API Key sudah dicabut, jadi tidak bisa diubah atau dirotasi. |

Cocokkan dengan `code`. Teks `message` ditujukan untuk dibaca manusia, dan bisa berubah.

## Error yang bisa diterima Customer

Selain _error_ inferensi yang biasa, batas yang Anda atur menolak _request_ Customer dengan _error_ berikut. Lihat [Error](/id/docs/errors).

- `402 spend_limit_reached`: API Key sudah mencapai Spend Limit-nya. _Request_ yang sudah berjalan tetap selesai, jadi `spent` bisa sedikit melewati batas. Key bisa dipakai lagi setelah Anda menaikkan atau menghapus Spend Limit-nya.
- `429 request_rate_exceeded`: API Key mengirim lebih banyak _request_ dalam satu menit daripada yang diizinkan Request Rate-nya. Customer bisa _retry_ dalam satu menit.
