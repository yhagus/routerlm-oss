# Gambar, audio, dan video

Selain _chat_, Model bisa punya salah satu dari empat Kind media. Setiap Kind punya _endpoint_ sendiri, dengan format _client_ SDK resmi yang sesuai (`client.images`, `client.audio`, dan `client.videos`):

| Kind | Endpoint |
| --- | --- |
| `image` | `POST /v1/images/generations`, `POST /v1/images/edits` |
| `speech` | `POST /v1/audio/speech` |
| `transcription` | `POST /v1/audio/transcriptions` |
| `video` | `POST /v1/videos`, `GET /v1/videos/{id}`, `GET /v1/videos/{id}/content` |

[`GET /v1/models`](/id/docs/models) menampilkan `kind` setiap Model. Model yang dikirim ke _endpoint_ untuk Kind lain, misalnya Model gambar ke `/v1/chat/completions` atau Model _chat_ ke `/v1/images/generations`, ditolak dengan `400 invalid_request`. Pesan _error_-nya menyebutkan kedua Kind tersebut.

Autentikasi dan _error_ di _endpoint_ ini sama dengan _endpoint_ _chat_ (lihat [Autentikasi](/id/docs/authentication) dan [Error](/id/docs/errors)). _Error_-nya memakai _error body_ Chat Completions. _Gateway_ selalu mengembalikan _byte_ hasilnya sendiri, tidak pernah tautan ke tempat hasil itu dibuat.

_Body_ JSON maksimal 20 MB. Di _multipart form_, setiap _file_ yang diunggah maksimal 25 MB. _File_ yang lebih besar ditolak dengan `413 request_too_large` sebelum ada yang diteruskan.

Blok JSON di bawah menunjukkan _request body_ dan _response_. Kirim dengan _HTTP client_ apa pun, dengan API Key di _header_ `Authorization`.

## Membuat gambar

`POST /v1/images/generations` menerima _body_ JSON:

```json
{
  "model": "my-image-model",
  "prompt": "A lighthouse at dawn, watercolor",
  "n": 2,
  "size": "1024x1024"
}
```

| Field | Arti |
| --- | --- |
| `model` | Wajib. Model dengan Kind `image`. |
| `prompt` | Wajib. Gambar yang ingin dibuat. |
| `n` | Jumlah gambar, dari 1 sampai 10. _Default_-nya 1. |
| `size` | `WIDTHxHEIGHT`, misalnya `1024x1024`, atau `auto` agar Model yang memilih. Jika tidak ada Route milik Model yang bisa membuat ukuran tersebut, _request_ ditolak dengan `400 no_capable_route` yang menyebutkan ukurannya. |
| `negative_prompt` | Hal yang tidak boleh muncul di gambar. |
| `seed` | Bilangan bulat dari 0 sampai 2147483647, agar hasilnya bisa diulang. |

_Response_-nya berisi setiap gambar sebagai base64 di `b64_json`:

```json
{
  "created": 1794700000,
  "data": [{ "b64_json": "iVBORw0KGgo..." }, { "b64_json": "iVBORw0KGgo..." }]
}
```

Yang berikut ditolak dengan `400 invalid_request`:

- `response_format` selain `b64_json`. _Gateway_ tidak pernah mengembalikan URL gambar.
- `stream`, dan `partial_images` selain 0.

## Mengedit gambar

`POST /v1/images/edits` menerima _field_ yang sama dengan pembuatan gambar, ditambah gambar _input_ sebagai titik awal: minimal 1 dan maksimal 16. Kirim dengan salah satu dari dua cara:

- **JSON:** _array_ `images` berisi objek `{ "image_url": "..." }`. Setiap `image_url` berupa URL `https://` atau `http://`, atau URL `data:image/...;base64,...`.
- **_Multipart form_:** setiap gambar diunggah sebagai _file_ di _field_ `image` (satu gambar) atau `image[]` (beberapa gambar), dengan _field_ lain sebagai _field_ _form_. Cara ini yang dipakai SDK.

```json
{
  "model": "my-image-model",
  "prompt": "Put the cat on the sofa",
  "images": [
    { "image_url": "https://example.com/cat.png" },
    { "image_url": "https://example.com/sofa.png" }
  ]
}
```

Route milik Model bisa menerima kurang dari 16 gambar _input_. Gambar _input_ yang melebihi batas semua Route ditolak dengan `400 no_capable_route`, dan pesannya menyebutkan batasnya. `mask` ditolak dengan `400 invalid_request`, begitu juga _file_ unggahan yang bukan gambar. _Response_-nya sama dengan _response_ pembuatan gambar.

## Speech

`POST /v1/audio/speech` mengubah teks menjadi audio:

```json
{
  "model": "my-speech-model",
  "input": "Your order has shipped.",
  "voice": "my-voice",
  "response_format": "mp3"
}
```

| Field | Arti |
| --- | --- |
| `model` | Wajib. Model dengan Kind `speech`. |
| `input` | Wajib. Teks yang akan diucapkan. |
| `voice` | Wajib. Diteruskan apa adanya, jadi harus berupa suara yang dikenal _upstream_ Model tersebut. Tanyakan ke operator _gateway_ suara apa saja yang dimiliki Model. Pengaturan operator untuk Model bisa memaksakan suara tertentu, dan pengaturan itu mengalahkan pilihan Anda. |
| `response_format` | `mp3` (_default_), `wav`, `pcm`, atau `opus`. |
| `speed` | Dari 0.25 sampai 4. |
| `instructions` | Diterima, tetapi tidak diteruskan: untuk sekarang belum berpengaruh. |

_Response body_-nya adalah audio itu sendiri, dengan _content type_ sesuai formatnya: `audio/mpeg`, `audio/wav`, `audio/pcm`, atau `audio/opus`.

Yang berikut ditolak dengan `400 invalid_request`:

- `response_format` lain, misalnya `aac` atau `flac`. _Gateway_ tidak pernah mengubah audio ke format yang tidak Anda minta.
- `stream_format` selain `audio`. _Speech_ belum mendukung _streaming_.

## Transkripsi

`POST /v1/audio/transcriptions` mengubah audio menjadi teks. _Endpoint_ ini menerima _multipart form_ dengan _field_ berikut:

| Field | Arti |
| --- | --- |
| `file` | Wajib. _File_ audio, maksimal 25 MB: aac, amr, flac, m4a, mp3, mp4, mpeg, ogg, opus, wav, atau webm. _Gateway_ membaca formatnya dari _content type_ _file_, atau dari nama _file_ jika tipenya generik, misalnya `application/octet-stream`. |
| `model` | Wajib. Model dengan Kind `transcription`. |
| `language` | Bahasa yang diucapkan, misalnya `en`, sebagai petunjuk untuk pengenalan suara. |
| `response_format` | `json` (_default_) atau `text`. |

Dengan `json`, _response_-nya berisi transkrip dan durasi audio dalam detik:

```json
{
  "text": "Your order has shipped.",
  "usage": { "type": "duration", "seconds": 2 }
}
```

Dengan `text`, _response body_-nya hanya berisi transkrip, sebagai `text/plain`.

Yang berikut ditolak dengan `400 invalid_request`:

- `response_format` lain, misalnya `srt`, `vtt`, atau `verbose_json`. Format ini butuh _timestamp_ yang belum dikembalikan _gateway_.
- `stream` bernilai `true`.
- _File_ yang formatnya tidak bisa dikenali _gateway_, atau yang bukan audio.

_Gateway_ mengabaikan `prompt`.

## Video

Pembuatan video butuh waktu beberapa menit. Jadi Anda memulai Video Job, melakukan _polling_, lalu mengunduh videonya setelah selesai.

### Memulai Video Job

`POST /v1/videos` menerima _body_ JSON, atau _multipart form_ dengan _frame_ pertama diunggah sebagai _file_ di _field_ `input_reference`:

```json
{
  "model": "my-video-model",
  "prompt": "A red fox runs through snow",
  "seconds": "5",
  "size": "1280x720"
}
```

| Field | Arti |
| --- | --- |
| `model` | Wajib. Model dengan Kind `video`. |
| `prompt` | Wajib. Apa yang terjadi di video. |
| `seconds` | Durasi, berupa bilangan bulat positif, sebagai angka atau _string_. _Default_-nya 5. `-1`, yang menyerahkan durasi ke _upstream_, ditolak dengan `400 invalid_request`: _gateway_ harus tahu durasinya saat _job_ dimulai. |
| `size` | `WIDTHxHEIGHT` dengan rasio aspek 16:9, 9:16, 1:1, 4:3, atau 3:4, misalnya `1280x720`. Sisi terpendeknya menentukan resolusi terdekat: 480P, 720P, atau 1080P. |
| `resolution` dan `aspect_ratio` | Pengganti `size`: `480p`, `720p`, atau `1080p`, dan salah satu rasio aspek di atas. Kirim `size` atau keduanya ini, jangan sekaligus. Tanpa semuanya, videonya 720P. |
| `seed` | Bilangan bulat dari 0 sampai 2147483647. |
| `input_reference` | _Frame_ pertama: `{ "image_url": "..." }`, atau _file_ yang diunggah di _multipart form_. |
| `frame_images` | _Frame_ pertama, _frame_ terakhir, atau keduanya: objek dengan `frame_type` bernilai `first_frame` atau `last_frame`, dan `image_url`. |
| `input_references` | Gambar referensi yang memandu video: objek dengan `image_url`. |

Setiap `image_url` berupa URL `https://` atau `http://`, atau URL `data:image/...;base64,...`. Nilainya juga boleh ditulis sebagai `{ "url": "..." }`, dan objeknya boleh berisi `"type": "image_url"`.

Kirim paling banyak satu _frame_ pertama, di `input_reference` atau `frame_images`, dan paling banyak satu _frame_ terakhir. Jika ada _frame_ pertama, video mengikuti rasio aspek _frame_ tersebut.

```json
{
  "model": "my-video-model",
  "prompt": "The fox turns toward the camera",
  "frame_images": [
    { "type": "image_url", "frame_type": "first_frame", "image_url": "https://example.com/start.png" },
    { "type": "image_url", "frame_type": "last_frame", "image_url": "https://example.com/end.png" }
  ]
}
```

Titik awal _request_ menentukan Route mana yang bisa melayaninya. Masing-masing butuh _capability_ sendiri: `text-to-video` untuk _prompt_ saja, serta `first-frame`, `last-frame`, atau `reference-images` untuk setiap jenis gambar yang Anda kirim. _Request_ yang tidak bisa dilayani Route mana pun milik Model ditolak dengan `400 no_capable_route`, dengan pesan yang menyebutkan apa yang kurang: _capability_, resolusi, durasi di luar rentang semua Route, atau gambar _input_ yang melebihi batas Route.

_Response_-nya adalah objek video dengan status `queued`. Simpan `id`-nya:

```json
{
  "id": "video_...",
  "object": "video",
  "status": "queued",
  "model": "my-video-model",
  "seconds": "5",
  "size": "1280x720",
  "created_at": 1794700000
}
```

`size` berisi `size` yang Anda kirim, atau `null` jika Anda mengirim `resolution` dan `aspect_ratio`.

### Polling Video Job

`GET /v1/videos/{id}` membalas dengan objek video yang sama dan `status` terbarunya: `queued`, `in_progress`, `completed`, `failed`, atau `expired`. _Job_ yang sudah selesai juga berisi `completed_at`, jika _upstream_ melaporkannya. _Job_ yang gagal berisi `error` dengan kode `video_generation_failed`.

### Mengunduh video

Setelah `status` bernilai `completed`, `GET /v1/videos/{id}/content` mengalirkan videonya sebagai `video/mp4`. Sebelum itu, _request_ ditolak dengan `409 video_not_ready`.

Id video hanya berlaku untuk API Key yang memulai _job_ tersebut. _Polling_ atau unduhan dengan id yang tidak diterbitkan _gateway_ untuk API Key Anda, atau _job_ yang sudah kedaluwarsa, ditolak dengan `404 video_not_found`. _Job_ yang sudah kedaluwarsa tidak bisa diunduh lagi: mulai _job_ baru.
